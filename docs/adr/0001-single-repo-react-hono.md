# ADR 0001：同仓库 React + Hono，统一开发与部署

- 日期：2026-10-28
- 状态：已采纳

## 背景

只有一名开发者配合 AI，熟悉 React 和 Next.js，曾在较复杂的 Next.js 项目遇到 Cloudflare 部署产物限制。产品重点是登录后的任务地图交互，不需要先实现复杂 SSR 或搜索引擎索引。

## 决策

采用 React + TypeScript + Vite、Hono、Cloudflare Vite 插件。一个 package.json、一个 npm 锁文件、一次构建发布；client/server/shared 分目录。前端作为 SPA 静态资源，业务 API 运行在 Worker。

Vite 是构建工具；React 是界面库；Hono 是 HTTP 框架。前后端边界不意味着必须拆成两个仓库和两个部署项目。

认证和数据访问预选 Better Auth 与 Drizzle，实际接入先验证。D1/R2 资源未开通前保留明确标识的只读示例，不构造伪持久化。

## 取舍

获得：继续使用 React 经验，单人维护，服务端依赖可控，同域认证和类型共享，较少框架渲染约定。

承担：页面路由、请求缓存、表单校验等需统一少量约定。公开课程的 SEO 如成为重点，需另做预渲染／SSR 决策。

不保证：轻量框架并不保证部署一定低于限制，必须持续检查实际产物；本地测试不能证明国内访问体验。

## 替代方案

Next.js 可继续使用但暂时没有足够的 SSR 需求支撑其新增运行和适配复杂度。独立前后端仓库增加当前阶段的发布和接口协作成本。需要新架构时补充 ADR，不静默替换。
