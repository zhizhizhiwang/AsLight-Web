# 产品与业务约束

本文件定义后续实现的业务规则。当前仅实现示例图谱与无环／解锁基础函数，不代表已完成以下持久化流程。

## 内容责任边界

教程、动作说明、教学顺序与考核文案由用户提供；开发者和 AI 负责系统功能、数据结构与内容录入能力。当前使用“主线1、主线2、主线3、支线1”等中性占位名称，详情统一标注“任务内容待添加”。不根据示例拓扑自行编写 Wota 艺教程或考核标准。

## 课程与图谱

课程包含章节；章节包含任务。每个任务有稳定 ID、主线／支线类型、内容、达标要求、地图位置、前置关系及发布状态。标题、序号、地图位置变化不能改变身份。

主支线不决定解锁规则。前置条件独立配置，支持 all（全部通过）和 any（至少一项通过）；无前置时可开始。发布时校验完整任务图，包含跨章节引用：禁止重复 ID、未知前置、重复边和任何循环。管理员画连线只是编辑，最终以后端发布校验为准。

成员可查看未解锁任务的说明，但不能提交。已通过任务不因后续课程编排调整而自动降级；新课程要求使用版本或新任务表达。归档保留历史引用。

## 状态分离

| 概念 | 状态                                                            | 变更依据                                 |
| ---- | --------------------------------------------------------------- | ---------------------------------------- |
| 解锁 | locked / available                                              | 根据已发布图谱与服务端确认的通过记录计算 |
| 学习 | not_started / in_progress / submitted / needs_revision / passed | 开始、提交、退回、审核通过               |
| 奖励 | not_earned / pending / delivered / not_applicable               | 是否有奖励、审核结果、管理员登记发放     |

奖励领取不参与解锁。没有奖励的任务照常完成。待领取显示红点，已领取显示绿点，同时必须显示文字或图标以便辨识。

## 提交与审核

1. 在线提交：服务端验证身份、解锁、文件归属和上传完成后创建新 attempt，记录任务版本。
2. 线下评审：管理员为指定成员创建线下 attempt，记录考核时间及备注，再通过同一个审核流程。
3. 通过：保留 review，更新 learning progress，若任务有奖励则创建一次 pending reward。
4. 退回：保存修改意见，显示 needs_revision；再次提交产生新 attempt，不覆盖旧视频／审核。
5. 奖励线下交付：管理员将 pending 改为 delivered，记录操作者和时间。成员无此写权限。

任何提交不等于通过。重复请求／并发审核必须使用状态条件和唯一约束，避免重复奖励或丢失审核结果。通知失败不回滚已完成审核；后续通过可重试通知机制处理。

撤销通过不是普通编辑入口：后续若实现，需要明确原因、权限、审计和下游已解锁任务处理策略；默认不级联清空进度。

## 待落地数据模型

| 实体                               | 关键数据与约束                                                           |
| ---------------------------------- | ------------------------------------------------------------------------ |
| users / identities / sessions      | 独立 user_id；同一供应商身份只能绑定一个用户；具体 auth 表由选定组件生成 |
| chapters / quests / quest_versions | 稳定身份、内容版本、发布／归档状态、展示坐标                             |
| quest_dependencies                 | 前置引用；发布时验证 DAG；每条边唯一                                     |
| user_quest_progress                | user_id + quest_id 唯一；服务器确认的进度                                |
| submissions                        | attempt、任务版本、本人、方式、视频对象 ID、时间                         |
| reviews                            | attempt、审核人、结论、意见、时间；重复审核控制                          |
| reward_grants                      | 用户、任务奖励定义、状态、发放人、时间；唯一授予约束                     |
| media_objects                      | owner、服务端对象 key、大小、格式、可用／删除状态                        |
| notifications / audit_events       | 通知与操作历史；不记录密钥、验证码或完整敏感资料                         |

写 schema 前确认 D1 的实际原子操作／批处理能力，不把任意 SQL 事务接口视为天然可用。多个管理员同时操作时必须有数据库级保护。

## 第一版产品边界

成员端：地图／列表、任务详情、登录、个人进度、视频提交、审核结果、奖励状态。管理员端：任务表单与前置配置、审核队列、线下登记、奖励登记。

第一版不包括自动动作识别打分、社交动态、排行榜、现金支付、复杂拖拽编课、自动发放实物或伪造官方 QQ 登录。
