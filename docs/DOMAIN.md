# 产品与业务约束

本文件定义业务规则。当前已实现账号、待激活成员管理、学习进度、线下考核申请／审核、奖励领取登记和课程即时编辑。B2 视频提交已接入且真实存储接口检查通过（网站内真实提交流程待验收）；正式教学与考核文案等待用户提供。

## 内容责任边界

内容编排与成员端交互遵循 [UI-UX](UI-UX.md)。章节、任务、图文素材和独立画布装饰由数据驱动；装饰不参与学习或解锁。内容编辑权限与成员管理、考核审核、奖励发放分离，由管理员向已激活账号单独授权。保存立即生效，他人刷新后查看；没有发布流程。

教程、动作说明、教学顺序与考核文案由用户提供；开发者和 AI 负责系统功能、数据结构与内容录入能力。当前使用“主线1、主线2、主线3、支线1”等中性占位名称，详情统一标注“任务内容待添加”。不根据示例拓扑自行编写 Wota 艺教程或考核标准。

## 课程与图谱

课程包含章节；章节包含任务。每个任务有稳定 ID、主线／支线类型、内容、达标要求、地图位置、前置关系及归档状态。标题、序号、地图位置变化不能改变身份。章节和任务都只能通过明确申请删除，不能仅从保存文档省略：服务端须确认没有任何学习、考核或奖励记录，且保存后的全部任务（包括归档任务）均不再引用它们。删除章节会连同章节内的全部任务一并删除，章节内有任一任务存在业务记录即拒绝；任务还需要不再被任何任务引用。可以在同一次保存中先明确移除相关前置关系，再删除未使用内容。有关联业务记录的章节或任务只能归档，不能靠删除、隐藏或修改文案清空历史。

未保存的新章节、新任务可从本页直接移除；已保存的章节和任务删除先确认，再随“保存修改”原子生效，删除章节时其任务一并删除。保存前可撤销并恢复移除时的本页内容；保存成功后暂无网页恢复入口。删除检查与课程版本更新、内容保存、删除审计在同一数据库 batch 中执行，失败全部回滚；并发开始学习与删除最多一方成功。删除审计保留原章节、任务定义、奖励设置、操作者、时间和版本，永久占用旧 ID，防止之后重建同名身份。

主支线不决定解锁规则。前置条件独立配置，支持 all（全部通过）和 any（至少一项通过）；无前置时可开始。保存时校验完整启用任务图，包含跨章节引用：禁止重复 ID、未知前置、重复边和任何循环；启用任务不能依赖已归档任务或章节。最终以后端保存校验为准。

例如“支线 A → 主线 B”表示 A 是 B 的前置，不会将 A 自动改为主线。B 采用 all 时，A 必须通过；B 采用 any 且还有其他前置时，通过其中一项即可，不一定需要 A。若 B 只有 A 一个前置，all 和 any 都要求 A 通过。通过以服务端学习记录为准，奖励未领取不影响解锁。

当前已有任一学习记录的任务不能直接修改前置条件或考核正文，应新增稳定 ID 的任务，并按需归档旧任务。名称、普通图文、位置和展示素材可以调整；不会更改通过或奖励记录。后续若支持学习要求版本迁移，必须另行明确旧进度如何适用。课程修改保留操作者、时间、原因及快照；并发保存使用课程版本拒绝覆盖，失败整体回滚。

成员可查看未解锁任务的说明，但不能提交。已通过任务不因后续课程编排调整而自动降级；新课程要求使用版本或新任务表达。归档保留历史引用。

## 状态分离

| 概念 | 状态                                                            | 变更依据                                     |
| ---- | --------------------------------------------------------------- | -------------------------------------------- |
| 解锁 | locked / available                                              | 根据当前可浏览图谱与服务端确认的通过记录计算 |
| 学习 | not_started / in_progress / submitted / needs_revision / passed | 开始、提交、退回、审核通过                   |
| 奖励 | not_earned / pending / delivered / not_applicable               | 是否有奖励、审核结果、管理员登记发放         |

奖励领取不参与解锁。没有奖励的任务照常完成。待领取显示红点，已领取显示绿点，同时必须显示文字或图标以便辨识。

## 提交与审核

1. 在线提交：服务端验证身份、解锁、文件归属和上传完成后创建新 attempt，记录任务版本。
2. 线下评审（已实现）：成员开始已解锁任务后申请考核，可附备注；管理员选择对应申请登记实际考核时间、通过或需修改。也可对已开始的任务直接登记线下考核，记录申请／登记人。每次尝试只有一条审核结论，退回必须填写反馈。
3. 通过：保留 review，更新 learning progress，若任务有奖励则创建一次 pending reward。
4. 退回：保存修改意见，显示 needs_revision；再次提交产生新 attempt，不覆盖旧视频／审核。
5. 奖励线下交付：管理员将 pending 改为 delivered，记录操作者和时间。成员无此写权限。

任何提交不等于通过。重复请求／并发审核必须使用状态条件和唯一约束，避免重复奖励或丢失审核结果。通知失败不回滚已完成审核；后续通过可重试通知机制处理。

线下流程使用进度版本和当前待审申请 ID 校验，页面数据过期时返回冲突并要求刷新。客户端同一内容的网络重试复用请求 ID；同一 ID 换内容会被拒绝。数据库 batch 原子保存进度、尝试、审核、奖励及审计，写入失败全部回滚。已通过任务没有重新审核或覆盖历史的网页入口。

管理员可设置全体成员共享的任务奖励说明，留空表示无奖励。通过时读取当时设置，将说明保存到审核和个人奖励记录；没有奖励的任务状态为 not_applicable。之后修改设置只影响未来通过，不补发或改写已有奖励。领取登记只允许管理员操作，记录实际操作者、登记时间和备注；重复请求不会重复登记。视频提交复用同一申请和不可覆盖的审核流程，支持通过／需修改与反馈，不新增数值评分体系。视频完成确认后绑定上传时固定的对象版本，成员只能将本人当前任务的未使用视频绑定到一次新尝试；绑定、进度和尝试在同一 D1 batch 原子写入。管理员删除视频不删除审核、进度或奖励。详见 [VIDEOS](VIDEOS.md)。

撤销通过不是普通编辑入口：后续若实现，需要明确原因、权限、审计和下游已解锁任务处理策略；默认不级联清空进度。

## 数据模型与后续扩展

| 实体                               | 关键数据与约束                                                           |
| ---------------------------------- | ------------------------------------------------------------------------ |
| users / identities / sessions      | 独立 user_id；同一供应商身份只能绑定一个用户；具体 auth 表由选定组件生成 |
| chapters / quests / quest_versions | 稳定身份、内容版本、启用／归档状态、展示坐标                             |
| quest_dependencies                 | 前置引用；保存时验证 DAG；每条边唯一                                     |
| user_quest_progress                | user_id + quest_id 唯一；服务器确认的进度                                |
| submissions                        | attempt、任务版本、本人、方式、视频对象 ID、时间                         |
| reviews                            | attempt、审核人、结论、意见、时间；重复审核控制                          |
| reward_grants                      | 用户、任务奖励定义、状态、发放人、时间；唯一授予约束                     |
| media_objects                      | owner、服务端对象 key、大小、格式、可用／删除状态                        |
| notifications / audit_events       | 通知与操作历史；不记录密钥、验证码或完整敏感资料                         |

写 schema 前确认 D1 的实际原子操作／批处理能力，不把任意 SQL 事务接口视为天然可用。多个管理员同时操作时必须有数据库级保护。

当前实际表名为 user、session、account、chapter、quest、progress、assessment_attempt、assessment_review、reward_grant 和 audit_event 等。尝试序号按成员与任务递增，同一任务仅一个待审尝试；每次尝试仅一条 review，每名成员每个任务仅一份奖励授予。课程版本和 video 媒体表已接入；通知仍属后续扩展。

## 第一版产品边界

成员端：地图／列表、任务详情、登录、个人进度、视频提交、审核结果、奖励状态。管理员端：任务表单与前置配置、审核队列、线下登记、奖励登记。

第一版不包括自动动作识别打分、社交动态、排行榜、现金支付、复杂拖拽编课、自动发放实物或伪造官方 QQ 登录。

## 当前账号约束

手机号只作未经归属验证的 11 位数字登录别称，不用于自动认领、合并或转移进度。管理员创建待激活成员并私下交付专属凭证；成员自行设置密码。恢复与换别称经管理员人工确认并审计，不发送短信／邮件。user_id 不因激活、重设或换别称变化。
