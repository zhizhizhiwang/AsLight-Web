# UI/UX 与内容编排要求

状态：2026-10-29 根据用户提出的六项要求固定产品方向；本文是后续实现约束，不表示功能已完成。实际进度见 [ROADMAP](ROADMAP.md)。

## 可行性与范围

六项要求均合理，可在现有 React、React Flow、Hono 和 D1 架构内逐步实现，无需更换框架。前五项确定成员端布局与交互，第六项需要课程数据、素材管理、独立编辑权限和即时保存一起支持，仅把页面常量改成 JSON 不能满足内容人员自行维护的目标。用户后续明确：不设置发布流程，有权限的人保存后立即生效，他人刷新即可查看。

本次固定信息结构、交互和内容可配置范围。FTB 式任务面板是布局与体验参考；配色、字体、节点外形、纹理和具体素材尚未定稿，不将现有样式认定为最终视觉稿。

## 统一控件与复用

成员页面与管理后台共用一套视觉规范和基础控件，后台入口复用侧栏导航项，不另写一种文字链接或按钮样式。普通操作使用共用按钮；页面跳转保留链接语义并复用按钮外观。允许主操作、次操作、轻量操作和图标操作表达层级，颜色、圆角、字号、点击高度、悬停、选中、禁用与键盘焦点统一维护。

当前基础组件位于 `src/client/ui.tsx`，对应样式与设计变量集中在 `src/client/ui.css`：`Button`、`ButtonLink`、`SidebarLink`、`Input`、`Select`、`Textarea`、`Field`、`Panel`。账号、成员管理、考核／奖励和任务详情已复用；后续编辑器也沿用。页面样式只负责排布，不通过父级选择器重新定义按钮与表单的外观。原生表单语义、输入限制、禁用和焦点行为必须保留，提交按钮显式指定 submit；普通按钮默认不提交表单。

地图节点、整行任务入口及背景关闭层属于专用交互，保留各自布局；不以此为由再建立第二套普通操作按钮。基础控件最小点击高度为 44px，长文案允许换行。

## 成员端固定要求

1. 整体参考 FTB 任务面板，以章节、任务节点和前置连线为核心，不增加独立宣传首页或大幅营销区域。
2. 主界面由左侧侧边栏与中央展示区组成，默认进入流程图。这里的“主界面”指整个任务面板，不等同于现有 `/overview` 概览子页。
3. 侧边栏展示可浏览的章节列表、当前章节和账号入口；管理员后台入口只对管理员显示。章节名称、图标与顺序由数据提供，不能写死“第一章”。章节较多时列表独立滚动，账号和管理入口保持可达。
4. 中央默认展示当前章节的任务节点、前置关系与章节素材，支持平移、缩放和回到合适视野。成员浏览时不能拖动修改节点位置或编辑连线。
5. 点击或键盘激活节点打开详情；内容包括用户提供的任务说明、前置任务、本人学习与奖励状态及当前可用操作。未解锁任务允许阅读说明，写操作由服务端确认资格。关闭详情后保留当前章节、筛选和地图视野，焦点返回触发节点。
6. 手机保留左侧导航，可收窄并展开章节列表；详情可使用适合窄屏的全屏弹层。不能把整张图强行缩小到节点无法点击，列表提供另一种浏览方式。

现有 `/flow`、`/tasks`、`/overview` 三个并列子页继续保留，默认仍为 `/flow`。列表与概览沿用当前章节，和地图读取同一份已保存课程及个人进度。章节、筛选、选中任务通过 React Router 与 URL 表达，直接访问、刷新、浏览器前进／后退应恢复对应内容；无效或归档引用显示明确提示。

跨章节前置任务显示来源章节和可跳转入口，不在当前章节伪造可完成的任务副本。锁定、学习中、待考核、通过、待领取等状态有文字或图标，不能只靠颜色区分。提供加载、空章节、请求失败重试和素材缺失时的替代显示。

## 数据驱动的范围

| 对象     | 无需修改代码的内容                                                    |
| -------- | --------------------------------------------------------------------- |
| 章节     | 稳定 ID、标题、说明、排序、图标、背景素材、初始视野与启用／归档状态   |
| 任务节点 | 稳定 ID、所属章节、标题、图标／图片、主支线属性、坐标、说明与考核内容 |
| 前置关系 | 前置任务引用、all/any 条件；连线根据同一关系生成                      |
| 详情内容 | 按顺序编排的标题、段落、列表和图片内容块；图片包含替代说明            |
| 画布装饰 | 独立图片／文字元素的素材引用、位置、尺寸、层级和替代说明              |

背景、装饰和任务节点分开建模。装饰不参与解锁、不计入学习进度，默认不拦截任务点击，不遮挡状态和必要连线。移动节点和修改素材不改变任务 ID，也不清空个人进度。

“无需改代码”指在已有内容类型和交互能力内增加章节、任务，调整排布、前置关系与图文素材；新增一种交互组件、考核机制或任意页面逻辑仍需开发。内容人员不需要改 React、SQL、迁移文件或部署网站。只支持受控内容块与展示选项，不开放任意 HTML、JavaScript 或全站 CSS 注入。

课程图片使用链接输入，兼容历史登记素材；支持复用、替换预览和缺图回退，不提供网页图片上传。新增图片文件放入 `public/course-assets/` 后随仓库部署，内容人员再填写 `/course-assets/...` 路径；也可填写无凭证的 HTTPS 公开图片链接。课程展示图片与成员作业视频分开管理，前者的展示方式不能使后者公开。课程图片由 Workers 静态资源或公开外链提供，成员视频独立存放 B2 私有桶。

## 内容人员的章节设计功能

用户要求章节设计功能只对负责文案／内容制作的人员开放。将“内容编辑”作为独立能力，与成员管理、考核审核和奖励发放权限分离；不能因为需要改文案就授予全部管理员权限。所有编辑数据接口均由服务端鉴权，普通成员不能通过直接请求读取编辑数据或保存课程。

权限与使用流程：

- 管理员：在成员管理中向已激活账号授予／撤销内容编辑权限，填写原因并留下审计。管理员自身也需要单独获得此能力。
- 内容人员：填写章节和任务、调整坐标与前置、填写图片链接并配置装饰，预览桌面／手机效果；点击保存即整体生效，没有草稿提交或发布步骤。
- 普通成员：刷新后读取最新课程和自己的进度，不显示编辑工具。浏览中的页面不会自动跳转或替换内容。

章节设计采用 FTB Quests 式的画布内编排：左侧章节、中央大画布，选中任务后按需打开属性面板。浏览与编辑共用节点外观、图文和依赖数据；编辑权限只改变可用操作，不另造一套课程展示。坐标输入保留作精确调整，不能成为主要定位方式。

2026-10-30 固定的交互方向：

- 空白处通过上下文操作新增任务，也提供可见的新增按钮；手机和键盘不依赖右键。
- 拖动节点调整排布；支持多选、框选及成组移动。选中任务后编辑标题、说明、图片、主支线和考核内容，属性面板可收起，画布保持主要空间。
- 从前置节点连接到后续节点配置依赖，支持分支、汇合与 all/any。连线和表单修改同一份关系；禁止自连、重复、循环以及对归档内容的有效依赖，服务端仍为最终校验者。
- 属性明确区分路线类型与前置条件，显示当前任务的解锁要求；支线可成为主线的必经前置。已有学习记录的任务提前禁用前置与考核编辑并说明原因，连线错误在画布附近显示。手机属性沿用全屏弹层和固定关闭入口。
- 图片和文字装饰与任务分开；装饰可以定位，但不进入学习依赖或统计，也不阻挡成员浏览时的节点操作。
- 保留独立只读预览以检查实际成员端详情和手机效果；编辑画布上的选择与拖动不产生个人学习记录。
- 保存即整体生效、他人刷新可见；保留权限、并发版本、历史与归档约束，不增加发布流程。

参考：[FTB Quests 官方编辑说明](https://feedthebeast.notion.site/7df10141fd1941db9fc43e90364d932c)、[官方编辑快捷操作定义](https://github.com/FTBTeam/FTB-Quests/blob/main/common/src/main/resources/assets/ftbquests/lang/en_us.json)。具体网页控件与触屏操作按本站场景适配，不照搬游戏鼠标按键。

保存前由服务端校验完整课程图，包含跨章节前置、稳定 ID、素材有效性和内容结构；拒绝未知引用、循环和失效素材。一次保存按一致版本原子生效，成员读取课程也使用一致快照。保留修改者、保存时间、原因与内容快照；用课程版本拒绝过期编辑覆盖。失败时保留本页修改，重新加载前明确提示会丢弃未保存内容。离开编辑页保留本页未保存状态，刷新／关闭页面由浏览器提示。

任务属性同时提供归档与删除：未保存的新任务直接移除；已保存但无学习／考核／奖励记录、且无其他任务引用时，经确认后随保存删除。否则禁用删除并说明原因，保留归档入口。保存前可撤销删除，恢复本页修改；保存后暂无网页恢复入口。服务端必须再次检查资格、保留删除审计并防止旧 ID 复用。章节目前仍只支持归档。调整标题、位置和素材保留历史；已有学习记录的任务禁止直接改前置或考核要求，应新增任务并归档旧任务。教学与考核正文仍由用户提供，系统只承载内容。

## 现有基础与缺口

更新至 2026-10-30；各轮验证范围分别记录在 ROADMAP：

- 已有侧边栏与中央区域、流程图／列表／概览、节点详情弹窗、个人状态和管理员后台。
- 任务定义已有稳定 ID、chapterId、position 与 prerequisites，地图按数据生成节点和连线。
- 已支持多章节加载、数据驱动的章节列表／文字图标／顺序，章节切换、URL 恢复及跨章节前置跳转；手机可展开章节列表。
- 已接入章节图片图标／背景／初始视野、任务图片、详情图文块及独立装饰的展示数据；地图、列表和详情共用素材解析与缺图回退，手机长详情支持全屏滚动。
- 已接入 `/content` 的章节／任务、图文块、独立编辑授权、即时保存及并发保护；支持以画布为主的放置、拖动、多选、复制、前置连接和装饰定位，属性面板按需打开，保留只读预览。已补充桌面操作和手机尺寸浏览器检查，真机触摸手势尚未验证，具体证据见 ROADMAP。图片采用链接输入与仓库部署；学习要求版本迁移仍未实现。展示及编辑协议见 [CONTENT](CONTENT.md)。

## 验收要求

- 内容人员通过页面新增第二章及任务，保存后其他成员刷新侧边栏即可出现新章节，无需改代码或重新部署。
- 修改标题、图片、节点坐标和装饰后正确展示；任务 ID、已有学习进度、考核历史与奖励记录保持不变。
- 隐藏章节与未公开素材不会通过成员课程接口泄露；普通成员直接调用编辑接口被拒绝，内容编辑者不能因此获得审核、发奖或成员管理权限。
- 保存拒绝循环、失效引用及无效素材；跨章节依赖能正确解释、导航和解锁，奖励领取不影响解锁。
- 桌面和手机均验证章节切换、缩放、节点打开／关闭、长内容滚动、键盘操作、返回及刷新；装饰不能阻挡这些操作。
- 保存失败不会留下部分生效数据；并发编辑不能静默覆盖。持久化、权限和路由按项目约定在真实本地 Worker/D1 验证。
