# 账号、登录别称与权限

状态：管理员预建成员、无邮箱激活、11 位数字别称登录及个人进度已实现，并通过真实本地 Worker/D1 验证。无需短信、邮件或 Resend。2026-10-31 已部署 aslighters.org；首个正式管理员已获所有者授权创建；2026-10-31 复核正式库时已确认激活，用户已反馈跑通一次线上流程，登录后的具体分支覆盖仍需补充记录。

## 身份模型

所有进度关联不可变 user_id。手机号仅作为用户选择的 11 位数字登录别称；不验证号码归属，不视为已验证手机号身份，不根据号码合并或迁移进度。任何 11 位数字都满足别称格式，不引入中国手机号号段规则或 +86 自动改写。

新账号 email 为真正的 NULL，email_verified 为 false，不生成假邮箱。旧账号邮箱作为遗留资料保留，不再用于登录或找回。旧邮箱邀请码／本地测试邮件表只保留原有数据，不再有读写入口。

## 开通与激活

1. 管理员在 /admin 创建待激活成员，仅填写成员名称；服务端固定 member 角色，分配稳定 ID。
2. 生成 256 位随机激活码，24 小时有效。明文只在当前响应显示；数据库仅存 SHA-256 摘要。由管理员通过已有私下联系或线下方式交给成员，网站不发送消息。
3. 成员在 /account 激活页填写专属凭证、11 位登录别称、昵称和密码。密码 10–128 字符，交给 Better Auth 默认 scrypt 处理，不降低安全参数。
4. 激活在 D1 原子 batch 中消费凭证、设置别称和凭据并记录审计。一次成功后不能复用；唯一别称冲突时整批回滚，凭证仍可使用。
5. 已激活成员使用别称＋密码登录。未激活账号不能登录，未激活与错误密码不会泄露不同的账号信息。

链接为 /account?mode=activate#code=凭证，恢复链接使用 mode=reset；凭证放 URL fragment，页面读入内存后 replace 清除地址中的 fragment。不存 localStorage，不通过日志或公开查询接口返回。

## 恢复、换别称与会话

成员忘记密码时联系管理员，由管理员通过既有关系人工确认本人身份并填写操作原因，再生成一小时有效的重设凭证。重发会使旧未使用凭证失效；领取并成功使用才修改密码，不让管理员知道成员密码。

管理员可为已激活普通成员修改别称，必须填写原因；不能按号码自动认领。修改成功使原会话和未使用凭证失效。别称冲突则所有改动回滚。

会话有效 7 天，HttpOnly、SameSite=Lax；HTTPS 使用 Secure。会话保存在 D1，禁用 Cookie 会话缓存。退出和退出其他设备使用 Better Auth。凭据版本随激活、重设、换别称递增，服务端同时校验用户与会话版本，阻止旧密码登录并发产生的迟到会话继续访问。

## 管理员初始化与恢复

`npm run auth:admin -- bootstrap --local` 只在无管理员时新建待激活管理员，凭证写入被忽略的 .cache/admin-access/*.txt。管理员自行设置密码，无预设口令或公开自助提权入口。重复执行不覆盖现有管理员。

拥有本机／平台运维权限者可用 `npm run auth:admin -- recover --local` 恢复唯一初始管理员；支持待激活时重发或激活后重设。此命令会轮换旧凭证，不能用于日常成员找回。远程操作必须显式 --remote 和 --origin=https://精确站点域名，并确认配置指向正确环境；当前默认库是开发库。

管理员后台只能创建普通成员，不能修改自己或其他管理员的凭据。成员列表中的别称脱敏。创建、重发、激活、重设、换别称记录操作者、目标、时间及原因；审计不存密码、原始凭证或完整别称。

## Better Auth 适配

沿用 1.7.14 minimal、Drizzle adapter 与 D1。自定义 aslight-alias 插件将核心 email 字段设为可选且不对外返回；增加别称登录接口，使用库的密码验证、会话创建和 Cookie 签发。不使用短信插件的 OTP 或临时邮箱流程。

外层路由仅开放别称登录、读取会话、列出会话、退出和撤销会话。旧邮箱注册／登录／验证／找回、短信 OTP、用户自行更新角色／身份的接口均返回 404。所有状态修改校验精确 Origin；认证和激活限流使用 D1 原子 UPSERT，不以隐藏按钮代替权限。

## 线下考核权限

成员只能读取和申请自己的考核，不能通过请求参数选择他人、确认通过或领取奖励。`/api/admin/learning/*` 与成员管理共用管理员鉴权、精确 Origin 检查和写入限流。线下通过／退回、奖励设置及领取登记都记录实际管理员及时间；成员历史返回审核反馈与姓名，不返回登录别称或认证凭证。新流程的越权、并发、幂等和回滚由独立 Worker/D1 集成测试覆盖。

## 内容编辑权限

内容编辑使用独立的 `content_permission`，不改变账号 role。管理员在成员管理中向已激活账号授予／撤销，须填写原因；自身也需要显式授权。权限变更校验版本并和审计原子写入。普通编辑者不能调用成员管理、审核、奖励设置或领取接口。

`/api/content/course` 每次读取及写入检查有效会话和编辑能力，写入另校验精确 Origin、限流、严格文档结构及课程版本，数据库更新点再次检查权限。保存即整体生效，其他人刷新可见，没有发布权或发布步骤。撤销后不能继续保存旧页面；客户端入口不能替代服务端鉴权。
