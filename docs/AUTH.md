# 账号、身份与权限

状态：设计约束，尚未接入认证。预选 Better Auth + Drizzle/D1，先做 Workers 兼容性验证后固定版本。

## 身份模型

进度、提交、奖励统一引用内部 user_id。邮箱、QQ、手机是外部登录身份。昵称、用户手填的 QQ 号或手机号不能证明身份，不能用来自动关联已有进度。

为当前个人／社团运营设计的首发路径：邀请码 + 已验证邮箱 + 密码；支持 QQ 邮箱，但称为“邮箱注册”。邀请码限制加入范围，不能代替邮箱验证或登录。邮件供应商和发信域名尚未选择，需要实测 QQ 邮箱等常用邮箱的投递与找回流程。

QQ、手机号在实际渠道开通后加入，UI 按真实启用能力显示入口，不展示可以点击但永远无法登录的按钮。

## QQ

使用 QQ 互联 OAuth，服务端处理回调、state、令牌交换和用户身份获取；供应商支持时使用 PKCE。以应用对应的不可变身份标识识别用户，不假设可获取真实 QQ 号码、手机或已验证邮箱。

授权成功可直接建号；不要强制 QQ 用户额外设置站内密码。认证库若要求邮箱字段，应先验证其无邮箱身份支持，不能伪造已验证邮箱来绕过模型。

普通网站接入涉及开发者审核、域名及回调地址。官方常规规则要求备案，FAQ 另有海外网站邮件申请说明；个人主体及当前域名能否通过以实际审核为准。

- [应用审核规范](https://wiki.connect.qq.com/网站审核规范/)
- [申请常见问题](https://wiki.connect.qq.com/常规问题-20170322/)

## 手机号

需可用的短信资质、签名和验证码模板，不仅是购买短信额度。腾讯云当时的规则要求个人账号借助合规企业授权资质或升级企业认证；其他供应商须单独核实。

- [腾讯云国内短信签名要求](https://cloud.tencent.cn/document/product/382/37794)

验证码短时有效、一次性消费、限制验证次数；按手机号、IP 等限流并设置每日费用上限。验证码不能写入日志。发送与找回接口避免泄露账号是否存在。手机号存规范化形式，展示时脱敏，不能在公开资料中直接暴露。

## 绑定和恢复

- 用户登录后主动绑定另一种方式；敏感操作重新验证当前身份和待绑定身份。
- 已属于其他账号的身份不能直接迁移；账号合并是单独设计的操作，需要双方所有权证明、冲突处理和审计。
- 不按相同昵称或未验证邮箱自动合并 QQ 与站内账号。
- 禁止解绑最后一个可用登录方式；更换手机号不能使用户永久丢失账号。
- 邮箱找回、会话撤销、账号注销与恢复边界必须在真实账号上线前实现和测试。

## 会话与授权

生产使用 HTTPS、HttpOnly、Secure、适当 SameSite 的同源 Cookie；状态修改请求验证来源并使用适当 CSRF 防护。不得把长期令牌放 localStorage。密码交由维护良好的认证组件安全处理。

角色初步为 member 和 admin。管理员由受控运维流程赋予，注册请求不接受用户自选管理员。每个写请求验证会话、角色、资源所有权与业务状态。成员只能查看自己的提交和私有视频；管理员操作写审计记录。
